# Website

This website is built using [Docusaurus 3](https://docusaurus.io/) (pinned to `3.6.3` in `package.json`), a modern static website generator. It is the source of the Ever® Demand documentation site (`https://docs.everdemand.co`).

## Requirements

- **Node.js** `>=18.17` (see `engines` in `package.json`; the locked `cheerio@1.0.0` does not install on older 18.x releases). The production Docker image is built with Node `26.12.1`, so a recent Node release is the safest choice.
- **Yarn classic (1.x)**. The repository ships a `yarn.lock`; the Docker build uses Yarn `1.22.22`.

## Installation

Run everything from the `website` folder:

```
$ yarn install
```

## Local Development

```
$ yarn start
```

This command starts a local development server on <http://localhost:3000> and opens up a browser window. Most changes are reflected live without having to restart the server.

## Available scripts

| Command | What it does |
| --- | --- |
| `yarn start` | Dev server with live reload. |
| `yarn build` | Production build into `website/build`. |
| `yarn serve` | Serves the `build` folder locally, to check the production output. |
| `yarn clear` | Clears the Docusaurus cache (`.docusaurus`, `build`). Use it when the dev server behaves strangely after a config or dependency change. |
| `yarn typecheck` | Runs the TypeScript compiler (`tsc`) over the site's TypeScript files (config, sidebars and `src/`). |
| `yarn spellcheck` | Runs [cspell](https://cspell.org/) using `.cspell.json` at the repository root. Add legitimate product or technical terms to its `words` list. |
| `yarn write-heading-ids . "docs/*.md"` | Adds explicit heading IDs to Markdown files, which keeps anchor links stable. It only processes the files you name, so pass the site directory and a file or glob argument (run without arguments it changes nothing). |

## Adding or editing a page

- Documentation pages live in `website/docs/` as Markdown files. Each file starts with front matter, for example:

  ```md
  ---
  id: support
  title: Support
  sidebar_position: 3
  ---
  ```

- The sidebar is generated automatically from the `docs/` folder (`sidebars.ts` uses `autogenerated`), so a new file shows up without editing any config. Use `sidebar_position` to control the order.
- Images and other static files go in `website/docs/assets/` (or `website/static/`); both folders are served from the site root (`staticDirectories` in `docusaurus.config.ts`). For example `docs/assets/overview.png` is referenced as `/overview.png`.
- Broken internal links fail the build (`onBrokenLinks: "throw"`), so run `yarn build` before opening a pull request. Broken Markdown links and broken `#anchor` links only produce warnings (`onBrokenMarkdownLinks: "warn"`; the anchor check is not configured and defaults to a warning in Docusaurus 3.6), so also read the build output for warnings.
- Every URL is emitted with a trailing slash (`trailingSlash: true`), matching how the site is served.
- Pull requests should target the `develop` branch.

## Environment variables

The configuration reads the following variables from the process environment. All are optional.

| Variable | Used for |
| --- | --- |
| `ALGOLIA_APP_ID`, `ALGOLIA_API_KEY`, `ALGOLIA_INDEX_NAME` | Algolia DocSearch. Search switches to Algolia only when **all three** are set. When any of them is missing, the site falls back to the built-in local search plugin (`@easyops-cn/docusaurus-search-local`). |
| `NEXT_PUBLIC_SENTRY_DNS` | Sentry DSN. Error reporting is enabled only for production builds (`NODE_ENV=production`, which `yarn build` sets) and only when this variable is non-empty. |

Things to be aware of:

- **`.env.example` uses different names.** It lists `APPLICATION_ID`, `API_KEY` and `INDEX_NAME`, but `docusaurus.config.ts` reads `ALGOLIA_APP_ID`, `ALGOLIA_API_KEY` and `ALGOLIA_INDEX_NAME`. Use the `ALGOLIA_*` names from the table above; the unprefixed names have no effect.
- **A `.env` file is not applied to these variables.** The config reads them into constants at the top of the file, before it calls `dotenv.config()`. Export them in your shell instead:

  ```
  $ export ALGOLIA_APP_ID=... ALGOLIA_API_KEY=... ALGOLIA_INDEX_NAME=...
  $ yarn start
  ```

## Languages (i18n)

Only the English locale is enabled (`locales: ["en"]` in `docusaurus.config.ts`). Translation sources for `ar`, `bg`, `de`, `es`, `fr`, `he`, `it`, `nl`, `pl`, `pt`, `ru` and `zh` exist under `website/docs/i18n/`, but they are intentionally not published: the Docker build runs `yarn build --locale en`, so any other locale listed in the config would appear in the language dropdown and return 404.

To publish another locale, **both** of these must be done:

1. Add it to `locales` in `docusaurus.config.ts`.
2. Remove the `--locale en` flag from the build command in `website/Dockerfile.everk8s`, so that every locale declared in the config is built. Do not replace it with a single other locale (for example `--locale fr`): a build limited to one locale emits only that locale and would drop the English site from the image.

## Docker image

The site is shipped as a static bundle served by nginx. From the repository root:

```
$ docker build -f website/Dockerfile.everk8s -t ever-demand-docs website
$ docker run --rm -p 8080:80 ever-demand-docs
```

The site is then available on <http://localhost:8080>. The build context is the `website` folder. `nginx-default.conf` sets `absolute_redirect off` so that trailing-slash redirects stay on the scheme the client used (for example HTTPS behind a TLS-terminating proxy) instead of downgrading to HTTP.

## Troubleshooting

- **Build fails with a module-not-found error for `docusaurus-theme-redoc`** – `docusaurus.config.ts` still lists `themes: ["docusaurus-theme-redoc"]`, but that package is not in `package.json` and the site has no OpenAPI spec. The Dockerfile deletes that one line before building. For a local build, remove the line yourself and do not commit the change. (This is taken from the comment in `Dockerfile.everk8s`; it was not reproduced locally.)
- **Stale content or odd errors after pulling changes** – run `yarn clear`, then `yarn start` again.
- **Build runs out of memory** – the Docker build raises the heap with `NODE_OPTIONS=--max_old_space_size=7168`; do the same locally if the full build fails with an out-of-memory error.

## Deployment

Production images are built by the `k8s-build` GitHub workflow from `website/Dockerfile.everk8s` on pushes to `develop`, `stage`, `main` and `master`. Pull requests do not publish anything.

The `yarn deploy` script (the stock Docusaurus GitHub Pages deploy) is still present in `package.json`, but it is not how this site is published.
